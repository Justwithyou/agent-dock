## 1. 背景与产品目标

　　团队中的 Prompt 与 Skill 已由 Git 资产仓库统一管理，但成员仍需在文件目录、Git 历史和不同 Agent 工具目录之间手工操作。桌面端提供可视化路径，帮助成员发现资产、核对版本与差异、准备恢复变更，并将可信快照安全分发到本机工具。

　　桌面端面向使用编程 Agent 的团队成员、资产负责人和工作区维护者。完成任务的可见证据是：用户找到目标资产，确认来源 revision 与文件范围，完成版本或分发操作，并能查看操作后的工作区状态、目标路径、来源 commit 及未处理项。

产品目标：

1. 用户无需记忆命令或各 AI 工具的目录约定，即可完成 Prompt 与 Skill 的查看、版本确认、恢复和分发。
2. 涉及标签移动、资产恢复或目标文件写入的操作，均在执行前展示对象、目标与影响，并由用户明确确认。
3. 资产、历史、版本标签和校验结果直接来自当前工作区，不建立桌面端私有资产副本。
4. 空仓库、非 Git 目录、配置错误、单资产损坏、目标冲突和写入失败均有明确的恢复路径。

## 2. 产品范围

### 2.1 MVP 范围

| 范围 | 交付内容 |
|---|---|
| 工作区 | 打开、初始化、刷新，以及空资产、非 Git、配置错误和读取失败状态 |
| 资产 | Prompt/Skill 列表、组合过滤、详情、源文件、工作区校验和单资产诊断 |
| 历史与差异 | 当前资产提交历史、双 revision 比较、文本差异和 Skill 资源变化 |
| 版本标签 | 创建不可变 `v*` 标签、显式移动 `prod`、展示完整标签与目标指向 |
| 回滚 | 选择目标快照、预览恢复范围、检查冲突、生成单资产未提交恢复变更 |
| 分发 | 资产、AI 工具、项目级/用户级、revision 与 Prompt 变量配置，自动目录解析、dry-run、冲突处理、执行结果与安全重试 |
| 高级自定义目录 | 在应用内为便携版、非标准目录或企业环境配置本机目标根目录；保留已有配置，仅高级模式使用 |
| 协作说明 | README、目录规范、Schema、owners、CODEOWNERS 说明和标准变更流程 |

### 2.2 不在当前范围内

- 不内置另一套资产编辑器、MR/PR 评审系统或团队权限系统；“新增资产”提供指引，变更仍通过 Git 评审进入仓库。
- 不自动提交、推送、合并或改写 Git 历史，不自动移动 `prod`。
- 不自动递归安装或分发 Skill 依赖，不执行 Prompt 表达式或 Skill 脚本。
- 不提供 MCP 注册、Eval、模型测试或 Agent 成功率评测入口。
- 不用符号链接替代复制式分发，不覆盖未纳管同名文件。

## 3. 共享业务规则

### 3.1 当前对象与 revision

　　资产详情、历史、版本标签和回滚均围绕当前选中的 `AssetRef` 展开。从资产详情进入分发时继承该资产；在历史页选择提交会更新“比较到”revision。资产或工作区变化后，旧的差异、分发计划和执行确认不得继续作为新对象的操作依据。

| 操作 | 默认或继承的 revision | 用户选择要求 |
|---|---|---|
| 资产列表与详情 | 当前工作区内容及资产发布信息 | 选择资产只切换页面上下文 |
| 历史列表 | 当前资产的提交历史，标识 HEAD | 可选择具体提交作为比较目标 |
| 差异比较 | 原型默认 `v1.1.0 → v1.2.0` | 两端均可显式选择版本标签、HEAD 或 commit |
| 创建版本标签 | HEAD | 可改为其他已提交 revision |
| 移动 `prod` | 历史页当前“比较到”revision | 必须在确认弹窗核对当前指向与目标指向 |
| 回滚 | 历史页当前“比较到”revision | 必须预览恢复范围后确认 |
| 分发 | 工作区发布通道 `prod`；标签不存在时回退 HEAD | 可显式改为 HEAD 或版本标签；不提供 working-tree 分发 |

### 3.2 分类标签、版本标签与回滚

- 分类标签用于资产筛选；版本标签用于定位 Git revision，两者在样式和含义上不得混用。
- 完整版本标签为 `adock/<kind>/<id>/<name>`。`v*` 为不可变版本标签，已存在时拒绝覆盖；`prod` 为可移动发布通道，移动前必须确认。
- 创建或移动版本标签不生成新的资产 revision，不修改资产正文，也不自动推送。
- 回滚只生成目标资产的未提交恢复变更，不是撤销提交；成功后不自动提交、推送或移动 `prod`。
- Prompt 按单文件恢复；Skill 按完整目录恢复，包括目标快照所需的资源文件变化。其他资产、分支和 Git 历史不受影响。

### 3.3 分发路径与冲突

　　标准分发不要求用户配置目录。用户选择目标 AI 工具和作用范围后，系统按工具官方约定自动解析目标根目录：项目级以当前工作区为基准，用户级以当前用户主目录为基准。页面只读展示解析后的目标位置，最终资产文件位置由适配规则决定，并以 dry-run 中列出的逐文件目标路径为准。

| 目标工具 | 项目级目录 | 用户级目录 |
|---|---|---|
| Claude Code | `<工作区>/.claude` | `<用户主目录>/.claude` |
| Cursor | `<工作区>/.cursor` | `<用户主目录>/.cursor` |
| Trae | `<工作区>/.trae` | 自动识别 `<用户主目录>/.trae-cn` 或 `<用户主目录>/.trae` |
| Codex | `<工作区>/.agents` | `<用户主目录>/.agents` |
| Workbuddy | `<工作区>/.codebuddy` | `<用户主目录>/.codebuddy` |

　　Trae 用户级只检测到 `.trae-cn` 时选择 CN，只检测到 `.trae` 时选择国际版，两者都不存在时默认 CN；两者同时存在时展示版本选择，未明确选择前禁止生成计划。标准模式忽略已有自定义目录；只有用户明确进入“高级自定义”后才读取并使用 `adock.local.yaml` 中的本机配置。切回项目级或用户级不删除已有自定义配置。

　　高级自定义输入的是工具官方目录的上一级基准目录，系统按目标工具自动追加官方目录。例如选择 `D:\AI\project` 作为 Trae 基准目录时，目标根目录解析为 `D:\AI\project\.trae`，Skill 最终写入其下的 `skills` 目录。若输入已经以目标工具的官方目录结尾，则直接使用，不重复追加。目标选项、已有配置回填与 dry-run 共用同一解析规则。

| 计划状态 | 业务含义 | 执行规则 |
|---|---|---|
| 新增 | 目标文件不存在 | 用户确认后允许写入 |
| 更新 | 已纳管文件可由所选快照更新 | 用户确认后允许写入 |
| 不变 | 目标内容与计划内容一致 | 不重复改写，结果中仍标识为不变 |
| 未纳管冲突 | 目标存在同名文件，但不在本地清单中 | 始终阻止本流程覆盖；移开文件或调整目标后重新 dry-run |
| 本地已修改 | 已纳管文件在上次分发后被本地修改 | 默认保留并阻止执行；仅用户明确确认覆盖上述文件后可继续 |

　　dry-run 不写入目标文件，正式执行沿用用户核对过的计划。返回修改资产、目标、revision 或变量后，原计划失效，必须重新生成。重试时重新检查目标状态；若计划发生变化，需要重新确认。

### 3.4 读取、确认与取消

- 刷新只重新读取 Git 与文件系统，不自动重试写操作，也不使用桌面私有资产缓存替代当前事实源。
- 移动 `prod`、生成恢复变更、正式分发和覆盖已纳管本地修改均需显式确认，覆盖确认不得扩展到未纳管文件。
- 取消打开、初始化、标签、回滚或分发相关操作时，不产生对应写入；关闭弹窗可通过取消按钮、关闭按钮、遮罩或 Esc。
- 桌面端不新增管理员登录态。共享仓库的推送、评审与合并权限仍由 Git 平台执行，owners 用于定位维护责任。
- Windows 界面中的扩展路径仅做展示清理：`\\?\C:\repo` 显示为 `C:\repo`，`\\?\UNC\server\share` 显示为 `\\server\share`。该规则适用于页面、弹窗、分发结果与诊断文本，不改变命令调用、配置保存或 Git 使用的真实路径，也不清理资产正文中的示例。

## 4. 页面需求

### 4.1 全局工作区框架

#### 页面目的

　　让用户在任何任务页面都能确认当前工作区、分支和状态，并进入资产、历史、分发或协作说明。

#### 入口

　　应用启动后显示；工作区打开、初始化或刷新后继续保留。

#### 区域与字段

| 区域/字段 | 展示与填写要求 |
|---|---|
| 工作区入口 | 显示工作区名称与路径；点击进入“打开或初始化工作区”弹窗 |
| 分支与状态 | 显示当前分支，以及“工作区正常”“配置错误”或“非 Git”状态 |
| 刷新 | 顶部固定入口；重新读取当前 Git 与文件系统 |
| 一级导航 | 资产、历史、分发、协作说明；资产导航显示当前资产数量 |
| 事实源说明 | 明示资产、历史与版本标签来自当前仓库，刷新不读取桌面私有缓存 |
| 用户标识 | 展示当前用户标识，不代表额外桌面端权限 |

#### 操作与反馈

| 操作 | 反馈与结果 |
|---|---|
| 切换一级导航 | 进入对应页面；历史沿用当前资产，从详情进入分发时继承当前资产 |
| 点击刷新 | 显示重新读取状态，完成后提示已重新读取 Git 与文件系统 |
| 点击工作区入口 | 打开工作区弹窗，当前页面事实保持不变，直到成功打开其他工作区 |

#### 状态与恢复

| 状态 | 页面表现与可恢复操作 |
|---|---|
| 正在打开或刷新 | 显示读取状态，避免将尚未返回的内容误展示为空 |
| 配置错误或非 Git | 顶部状态同步标识；主区显示对应诊断页，协作说明仍可访问 |
| 工作区切换 | 清除上一工作区页面上下文，重新读取资产与状态 |

#### 权限与写入边界

　　导航与刷新均为只读操作。原型中的“原型场景”选择器仅用于评审正常、空仓库和异常场景，不属于正式产品功能。

### 4.2 打开工作区弹窗与工作区状态页

#### 页面目的

　　帮助首次使用或需要更换目录的用户进入有效工作区，并在无法继续时说明具体原因和修复方向。

#### 入口

　　点击顶部工作区入口；配置错误页可点击“重新选择工作区”，非 Git 状态页可点击“打开其他工作区”。

#### 区域与字段

| 区域/字段 | 展示与填写要求 |
|---|---|
| 工作区路径 | 必填；默认展示当前路径，允许输入其他本地目录 |
| 查找说明 | 明示将向上查找 `adock.yaml`，并检查仓库与配置状态 |
| 当前仓库信息 | 展示当前分支；说明共享配置与本机覆盖配置按既定优先级合并，本机路径不写回共享文件 |
| 打开工作区 | 校验并打开所填目录 |
| 初始化新工作区 | 转入初始化弹窗，不直接修改当前目录 |

#### 操作与反馈

| 操作 | 反馈与结果 |
|---|---|
| 打开有效工作区 | 关闭弹窗，刷新资产视图，并提示工作区已打开 |
| 打开异常目录 | 保留路径，展示对应状态页与诊断，不自动改写资产或配置 |
| 取消或关闭 | 返回原页面，当前工作区不变 |
| 转入初始化 | 展示独立初始化弹窗；返回后可继续打开工作区 |

#### 状态与恢复

| 状态 | 页面表现与可恢复操作 |
|---|---|
| 路径为空 | 提示输入工作区路径，不执行打开 |
| 正在打开 | 展示正在定位仓库与配置的状态，避免重复提交 |
| 空资产仓库 | 显示“工作区还没有能力资产”；诊断区分别显示 `prompts/` 与 `skills/` 数量；提供“新增资产”和“查看目录规范” |
| 配置错误 | 显示配置文件、字段、错误值和修复建议；提供“修复后刷新”和“重新选择工作区”；不自动改写配置 |
| 非 Git 工作区 | 显示目录及未找到 `.git` 的说明；历史、标签、回滚和分发不可继续；提供打开其他工作区和初始化说明 |
| 读取失败 | 保留路径，说明检查目录权限与配置，可重试或重新选择 |
| 单资产损坏 | 不得显示为空仓库；进入资产页定位具体错误资产 |

#### 权限与写入边界

　　打开、校验和刷新均不修改资产内容。非 Git 或配置无效时，不依赖不完整状态继续执行版本或分发写操作。

### 4.3 初始化新工作区弹窗

#### 页面目的

　　在空目录中创建可供团队协作的标准资产工作区，并在确认前让用户知晓创建范围。

#### 入口

　　在“打开或初始化工作区”弹窗点击“初始化新工作区”；非 Git 状态页可先查看初始化说明。

#### 区域与字段

| 区域/字段 | 展示与填写要求 |
|---|---|
| 空目录路径 | 必填；仅允许在空目录中初始化 |
| 资产配置 | 预览 `adock.yaml` 与 `schemas/` |
| 能力目录 | 预览 `prompts/` 与 `skills/` |
| 统一入口 | 预览 `README.md` 与 `CODEOWNERS` |
| 示例资产 | 明示包含 1 个 Prompt 与 1 个多文件 Skill |

#### 操作与反馈

| 操作 | 反馈与结果 |
|---|---|
| 确认初始化 | 按预览范围创建示例工作区，完成后重新读取资产并给出成功反馈 |
| 返回 | 回到打开工作区弹窗，不创建文件 |
| 取消或关闭 | 不创建或修改文件 |

#### 状态与恢复

| 状态 | 页面表现与可恢复操作 |
|---|---|
| 路径为空 | 提示输入初始化目录 |
| 目录非空 | 阻止静默覆盖，要求更换空目录 |
| 正在初始化 | 展示处理中状态，避免重复确认 |
| 初始化失败 | 保留可修复信息并显示失败原因，不提示初始化成功 |

#### 权限与写入边界

　　写入仅限用户明确选择的空目录及预览列出的工作区内容，不覆盖已有非空目录，不自动提交或推送。

### 4.4 资产列表与详情页

#### 页面目的

　　帮助用户发现可用 Prompt 与 Skill，并在进入历史或分发前确认用途、负责人、发布信息、变量或依赖及源文件范围。

#### 入口

　　打开有效工作区后的默认页面；也可通过一级导航“资产”或分发结果页“返回资产”进入。

#### 区域与字段

| 区域/字段 | 展示与填写要求 |
|---|---|
| 页面操作 | 提供“校验工作区”和“新增资产” |
| 搜索 | 按名称、ID 或说明匹配 |
| 组合过滤 | 支持资产类型、负责人和分类标签；默认均为全部 |
| 列表摘要 | 显示筛选后的资产数量及排序说明 |
| 资产列表项 | 显示类型、标题、`AssetRef`、说明、负责人、分类标签和版本；损坏资产增加错误标识 |
| 详情头部 | 显示类型、标题、`AssetRef`、源文件或 Skill 目录、说明，以及“查看历史”“进入分发” |
| 发布信息 | 显示 `prod` 当前指向、最新版本、已创建版本标签和 HEAD 短 SHA |
| 资产信息 | 显示负责人、分类标签、`adock/v1alpha1` 版本和校验状态 |
| Prompt 变量 | 表格列出变量、说明、是否必填和默认值；明示显式传值时才渲染 |
| Prompt 正文 | 展示 Markdown 正文，不执行表达式 |
| Skill 信息 | 展示触发条件、依赖声明和入口；明示不递归安装依赖 |
| Skill 正文 | 展示 Skill 指令正文 |
| 源文件 | Prompt 显示单文件；Skill 显示指令、脚本、参考材料等完整文件清单及文件数 |

#### 操作与反馈

| 操作 | 反馈与结果 |
|---|---|
| 输入搜索或修改过滤 | 即时更新列表与数量，仅影响当前视图，不修改资产 |
| 选择资产 | 更新选中态和右侧详情，为历史、回滚及从详情进入的分发提供当前对象 |
| 清除过滤 | 恢复全部过滤条件并重新展示资产 |
| 校验工作区 | 反馈全部通过数量，或通过与错误数量；单资产错误仍可在详情中定位 |
| 新增资产 | 打开新增资产指引，说明通过 Git 评审接收变更 |
| 查看历史 | 进入当前资产的历史与差异页 |
| 进入分发 | 以当前资产打开分发配置页 |

#### 状态与恢复

| 状态 | 页面表现与可恢复操作 |
|---|---|
| 正在读取列表或详情 | 显示读取状态或详情占位，不将加载中内容展示为空资产 |
| 无筛选结果 | 显示“没有符合当前条件的资产”及“清除过滤” |
| 空资产仓库 | 显示工作区空状态与目录诊断，不显示伪造的详情 |
| 单资产解析失败 | 列表标记错误；详情显示具体文件、行号、原因和修复建议；提供查看规范与重新校验 |
| 其他正常资产 | 在单资产损坏时仍可查看和操作，不被整体错误阻断 |
| 校验失败 | 保留资产级诊断，修复后可重新校验或刷新 |

#### 权限与写入边界

　　列表、过滤、详情和校验均为只读操作。页面不提供资产正文编辑；Skill 依赖仅提示，不自动安装，查看脚本不代表执行脚本。

### 4.5 历史与差异页

#### 页面目的

　　让用户核对当前资产的真实提交历史和两个明确快照之间的变化，再决定创建标签、移动发布通道或恢复资产。

#### 入口

　　点击一级导航“历史”或资产详情“查看历史”。

#### 区域与字段

| 区域/字段 | 展示与填写要求 |
|---|---|
| 当前资产说明 | 显示 `AssetRef`，并说明仅列出影响当前 Prompt 文件或 Skill 目录的提交 |
| 页面操作 | 提供“创建版本标签”“移动 prod” |
| 提交历史 | 每项显示短 SHA、提交说明、作者、时间、关联版本标签及 `prod` 标识 |
| 比较从 | 可选择版本标签、HEAD 或 commit，作为旧快照 |
| 比较到 | 可选择版本标签、HEAD 或 commit，作为目标快照；点击历史提交时更新此端 |
| 展示方式 | 支持“并排”和“统一”两种文本差异视图 |
| 差异摘要 | 显示变更数量、新增与删除行数及“Git 快照”来源 |
| Prompt 差异 | 以删除、新增和上下文样式展示正文变化；并排视图标明旧快照与目标快照 |
| Skill 资源差异 | 按目录展示资源新增、修改、删除和二进制变化，包含路径及可用的大小或行数说明 |
| 恢复入口 | 提供“恢复到此版本”，目标为当前“比较到”revision |
| 回滚结果提示 | 已生成恢复变更时，说明未提交、未改写历史、未移动 `prod`，并指引正常 MR/PR 流程 |

#### 操作与反馈

| 操作 | 反馈与结果 |
|---|---|
| 选择提交 | 更新“比较到”及对应差异，选中历史项 |
| 修改任一比较端 | 重新展示两个快照的差异，不修改工作区 |
| 切换并排或统一 | 只改变差异呈现方式，比较两端不变 |
| 创建版本标签 | 打开当前资产的不可变标签弹窗 |
| 移动 prod | 打开发布通道确认弹窗 |
| 恢复到此版本 | 打开回滚预览与确认弹窗 |

#### 状态与恢复

| 状态 | 页面表现与可恢复操作 |
|---|---|
| 正在读取历史或差异 | 显示读取状态，不以空白差异冒充无变化 |
| 暂无提交历史 | 明确显示该资产暂无历史，与读取失败区分 |
| revision 不存在或资产在快照中不存在 | 指出具体对象和原因，允许重新选择或刷新 |
| Git 读取失败 | 保留当前资产与比较输入，显示错误和重试路径 |
| 已存在恢复变更 | 页面顶部显示未提交恢复提示，不自动提交 |

#### 权限与写入边界

　　历史查询和差异比较本身只读。标签、发布通道和恢复写入分别由对应弹窗独立确认，不因查看差异而触发。

### 4.6 创建不可变版本标签弹窗

#### 页面目的

　　让资产负责人基于明确的已提交 revision 创建可追溯版本，并防止标签落到错误资产或覆盖已有版本。

#### 入口

　　在历史与差异页点击“创建版本标签”。

#### 区域与字段

| 区域/字段 | 展示与填写要求 |
|---|---|
| 资产 | 只读显示当前 `AssetRef` |
| 标签名 | 必填，示例为 `v1.3.0`；必须以 `v` 开头，`v` 后首字符须为字母或数字，后续可使用字母、数字、点、下划线或连字符，不得包含连续 `..` |
| 基于 revision | 默认 HEAD，可选择其他已提交 revision |
| 完整标签预览 | 随输入实时展示 `adock/<kind>/<id>/<tag>` |
| 错误区域 | 显示格式错误或重名原因 |
| 操作按钮 | 提供取消与“创建版本标签” |

#### 操作与反馈

| 操作 | 反馈与结果 |
|---|---|
| 输入标签名 | 更新完整标签预览并清除上一输入错误 |
| 创建有效标签 | 关闭弹窗，刷新详情发布信息和 revision 选项，提示完整标签已创建且未自动推送 |
| 取消或关闭 | 不写入标签或资产文件 |

#### 状态与恢复

| 状态 | 页面表现与可恢复操作 |
|---|---|
| 名称为空或格式无效 | 停留弹窗并给出有效 `v*` 示例 |
| 标签已存在 | 明确提示不可变版本标签不能覆盖，不执行创建 |
| 正在创建 | 显示处理中状态，避免重复提交 |
| 创建失败 | 在弹窗内显示对象与原因，保留可修正输入 |

#### 权限与写入边界

　　只创建当前资产的本地版本标签，不修改资产内容、提交历史或其他资产，不自动推送；后续共享权限由 Git 平台决定。

### 4.7 移动 `prod` 确认弹窗

#### 页面目的

　　让用户明确理解发布通道将从哪个 revision 移到哪个 revision，避免把通道变更误认为资产内容变更。

#### 入口

　　在历史与差异页点击“移动 prod”；目标指向取当前“比较到”revision。

#### 区域与字段

| 区域/字段 | 展示与填写要求 |
|---|---|
| 当前指向 | 显示当前资产 `prod` 指向的 revision |
| 目标指向 | 显示即将使用的 revision |
| 完整标签 | 显示 `adock/<kind>/<id>/prod` |
| 影响说明 | 说明移动后，团队成员默认分发将解析到目标 revision；不会修改资产内容或自动推送 |
| 操作按钮 | 提供取消与“确认移动 prod” |

#### 操作与反馈

| 操作 | 反馈与结果 |
|---|---|
| 确认移动 | 更新详情发布通道、历史 `prod` 标识和默认分发解析结果，提示未修改资产或推送标签 |
| 取消或关闭 | 保持当前指向不变 |

#### 状态与恢复

| 状态 | 页面表现与可恢复操作 |
|---|---|
| 目标无效或预览失效 | 不移动标签，提示重新选择目标并确认 |
| 正在移动 | 显示处理中状态，避免重复提交 |
| 移动失败 | 保留当前指向并显示失败原因，不提示发布成功 |
| 用户取消 | 不改变标签、资产或分发内容 |

#### 权限与写入边界

　　只移动当前资产的 `prod` 标签，不生成资产新 revision，不改写工作区文件，不自动提交或推送。

### 4.8 回滚预览与确认弹窗

#### 页面目的

　　将单个资产恢复到所选快照，同时保留完整 Git 历史和其他本地工作，并让用户在写入前核对恢复范围。

#### 入口

　　在历史与差异页点击“恢复到此版本”。

#### 区域与字段

| 区域/字段 | 展示与填写要求 |
|---|---|
| 当前工作区 | 标识为 `working-tree` |
| 目标快照 | 显示当前“比较到”revision |
| 恢复范围 | 逐文件显示路径和变化类型；Prompt 仅列对应文件，Skill 列完整目录文件 |
| 工作区检查 | 显示目标资产路径是否存在未提交修改 |
| 影响说明 | 说明只恢复当前 `AssetRef`，不影响其他资产、分支和 Git 历史，不自动提交或移动 `prod` |
| 操作按钮 | 提供取消与“确认生成恢复变更” |

#### 操作与反馈

| 操作 | 反馈与结果 |
|---|---|
| 确认恢复 | 生成目标资产的未提交恢复变更；历史页显示结果提示，并反馈未自动提交或移动 `prod` |
| 查看恢复结果 | 通过历史差异和正常 MR/PR 指引继续审查 |
| 取消或关闭 | 不生成恢复变更 |

#### 状态与恢复

| 状态 | 页面表现与可恢复操作 |
|---|---|
| 正在生成预览 | 显示读取与检查状态，暂不开放写入确认 |
| 目标资产路径有未提交修改 | 默认阻止恢复并指出冲突路径；其他资产的脏状态不得误阻止本资产 |
| 目标快照不可用 | 说明具体 revision 与原因，返回历史重新选择 |
| 预览因外部变化失效 | 要求重新预览，不继续沿用旧确认 |
| 写入失败 | 不描述为已回滚；保留错误原因，修复后重新预览并执行 |
| 恢复成功 | 明确标识为“未提交恢复变更”，而非已提交或已发布 |

#### 权限与写入边界

　　写入范围仅为当前资产路径。Skill 可恢复目标快照所需的目录资源变化，但不得触及其他资产、分支、提交历史或发布通道。

### 4.9 分发配置页（第 1 步）

#### 页面目的

　　让用户按“选择资产 → 选择 AI 工具 → 选择项目级或用户级 → dry-run → 执行分发”的主流程完成操作。标准模式自动解析官方目录，用户只需确认已提交快照，并补齐 Prompt 变量或了解 Skill 依赖。

#### 入口

　　点击一级导航“分发”，或从资产详情点击“进入分发”；后者继承当前资产。页面步骤条标识“1 配置分发”。

#### 区域与字段

| 区域/字段 | 展示与填写要求 |
|---|---|
| 资产 | 下拉选择可分发的 Prompt 或 Skill，显示标题与 `AssetRef` |
| 目标 AI 工具 | 标准模式列出支持当前资产类型的全部内置工具，不要求预先配置；高级模式仅列出已有自定义配置且受支持的目标 |
| 作用范围 | 提供“当前项目”“用户级”“高级自定义”；默认当前项目，项目级与用户级均自动解析目录 |
| Trae 版本 | 仅用户级同时检测到 CN 与国际版目录时显示；必选，未选择时禁用 dry-run |
| 自动目标位置 | 只读展示所选工具和作用范围对应的目标根目录；Trae 版本未确定时显示“选择 Trae 版本后自动确定”，不展示伪确认路径 |
| 高级自定义入口 | 明示用于便携版、非标准目录和企业环境；进入后读取已有本机配置，不影响标准模式 |
| 来源 revision | 默认使用当前资产的 `prod`；该标签不存在时回退 HEAD 并显示说明，不自动创建或移动标签。也可选择 commit 或版本标签，无需切换当前分支，不提供 working-tree |
| Prompt 必填变量 | 按当前资产显示，例如 `component`；未提供值时阻止 dry-run |
| Prompt 可选变量 | 按当前资产显示，例如 `focus`；显式值优先于变量声明中的默认值 |
| Skill 依赖提示 | 展示依赖声明，说明仅提示、不递归分发，执行过程不运行 Skill 脚本 |
| 分发前检查 | 汇总资产类型、来源、当前 `(kind, target)` 组合及“复制 / 渲染文件”方式 |
| dry-run 说明 | 明示不会写入目标文件，未纳管同名文件始终不会被覆盖 |
| 主操作 | 提供“生成 dry-run 计划” |

#### 操作与反馈

| 操作 | 反馈与结果 |
|---|---|
| 切换资产、目标、作用范围、Trae 版本或 revision | 更新分发前检查与目标位置；已有计划及执行结果失效，需按新输入重新生成 |
| 进入高级自定义 | 使旧计划失效并读取本机自定义目标；读取成功后一次点击直接打开管理弹窗，保留当前资产上下文；读取失败时停留当前页并提供重试 |
| 返回项目级或用户级 | 恢复标准自动目录解析，不删除自定义配置 |
| 填写 Prompt 变量 | 清除对应输入错误，显式值用于后续渲染 |
| 生成 dry-run | 仅在目标目录解析完成、必填输入有效且 Trae 歧义已处理后可用；此操作不写目标文件 |
| 管理自定义目录 | 打开“高级自定义目录”弹窗，保存后刷新高级模式目标选项 |

#### 状态与恢复

| 状态 | 页面表现与可恢复操作 |
|---|---|
| 未选择可读取资产 | 提示先选择资产；损坏资产需先修复，可返回资产页选择其他正常资产 |
| 正在解析工具目录 | 显示读取状态并禁用 dry-run，暂不使用旧目标位置生成计划 |
| 目录解析失败 | 显示原因和“重试解析目标”；可切换作用范围或进入高级自定义 |
| 默认 `prod` 不存在 | 默认版本切换为 HEAD，显示回退原因；允许继续 dry-run，不伪造 `prod` 标签 |
| 标准模式无受支持工具 | 禁用目标选择与 dry-run，说明当前资产类型的支持范围 |
| 高级模式无已配置目标 | 显示自定义目录添加入口，也可返回项目级或用户级，无需手动编辑配置文件 |
| 同时存在两个 Trae 用户目录 | 显示 CN/国际版选择；未选择时目标位置保持待定且禁止 dry-run，后端同样拒绝生成计划 |
| 必填 Prompt 变量为空 | 在配置区显示缺失变量，停留当前步骤并保留其他输入 |
| 目标组合不受支持 | 不生成空计划，要求选择受支持组合 |

#### 权限与写入边界

　　本步骤只读取资产、版本、用户主目录中的工具目录存在性及高级模式所需的本机配置。生成 dry-run 不写目标文件，不执行 Prompt 表达式或 Skill 脚本，不递归安装依赖。

### 4.10 dry-run 预览与确认页（第 2 步）

#### 页面目的

　　在正式写入前，让用户核对来源 commit、目标根目录、逐文件目标路径、内容校验和及冲突状态。

#### 入口

　　在分发配置页成功生成 dry-run 后进入；步骤条标识“2 预览与确认”。

#### 区域与字段

| 区域/字段 | 展示与填写要求 |
|---|---|
| 计划摘要 | 显示 `AssetRef`、目标工具、完整来源 commit 和实际目标根目录；该根目录可能来自标准作用域解析或高级自定义配置 |
| 状态统计 | 分别统计新增、更新、不变及冲突项，并说明计划不会执行脚本 |
| 文件计划表 | 每行显示状态、最终目标路径和校验和 |
| 未纳管冲突提示 | 显示阻止原因，指引移开文件、调整目标工具或作用范围后重新 dry-run，不提供覆盖选项 |
| 已纳管本地修改提示 | 说明默认保留本地修改，只有明确确认后才用所选 Git 快照覆盖 |
| 覆盖确认 | 仅在存在已纳管本地修改时显示；默认不勾选，文案限定为“上述已纳管文件” |
| 返回修改 | 返回配置步骤并使当前计划失效 |
| 确认并执行 | 仅在无阻塞冲突且所需覆盖均已明确确认时可用 |

#### 操作与反馈

| 操作 | 反馈与结果 |
|---|---|
| 核对计划 | 逐文件确认状态、路径和校验和；页面本身不写文件 |
| 勾选覆盖确认 | 仅允许覆盖计划中列出的已纳管本地修改，不改变未纳管冲突规则 |
| 返回修改 | 回到配置步骤，放弃当前计划和覆盖确认 |
| 确认并执行 | 沿用当前计划写入目标文件，随后进入执行结果页 |

#### 状态与恢复

| 状态 | 页面表现与可恢复操作 |
|---|---|
| 正在生成计划 | 显示正在读取 Git 快照并检查目标状态，避免重复提交 |
| 计划生成失败 | 显示操作对象、原因和修复建议，可返回修改后重试 |
| 未纳管同名冲突 | 禁用执行，显示冲突路径与解决指引；调整后重新 dry-run |
| 已纳管本地修改且未确认 | 默认阻止执行，保留本地修改 |
| 已纳管本地修改且已确认 | 允许继续，但确认范围不扩展到其他文件 |
| 全部文件不变 | 可完成核对，不重复改写资产文件 |
| 执行前目标状态变化 | 不静默沿用旧计划，要求重新 dry-run 和确认 |
| 正在执行 | 显示处理中状态，避免重复执行 |

#### 权限与写入边界

　　只有“确认并执行”会写目标文件。不得覆盖未纳管同名文件，不修改共享仓库资产或 Git 历史，不执行被分发脚本。

### 4.11 分发执行结果页（第 3 步）

#### 页面目的

　　清晰呈现成功、未写入和失败项，保留来源追溯信息，并在部分失败时提供安全重试路径。

#### 入口

　　在 dry-run 预览页确认执行后进入；步骤条标识“3 执行结果”。

#### 区域与字段

| 区域/字段 | 展示与填写要求 |
|---|---|
| 结果标题 | 成功显示“分发已完成”；存在失败时显示“分发未完成” |
| 结果说明 | 说明资产快照与目标工具；成功时说明目标侧清单已记录来源，失败时说明已写入和未处理情况 |
| 来源 commit | 显示完整 commit SHA |
| 目标工具 | 显示本次执行目标 |
| 处理结果 | 显示已核对、已写入和未处理数量，不将部分失败汇总为成功 |
| 文件结果表 | 逐行显示文件名、状态和目标路径；区分已写入、不变和未处理 |
| 失败诊断 | 显示失败原因与修复建议，例如目标目录不可写时检查权限 |
| 后续操作 | 成功时可继续分发其他资产或返回资产；失败时可修复后重试或返回资产 |

#### 操作与反馈

| 操作 | 反馈与结果 |
|---|---|
| 继续分发其他资产 | 返回分发配置步骤，清除本次结果和计划 |
| 修复后重试 | 重新检查目标状态并处理剩余文件；计划变化时重新确认 |
| 重试成功 | 更新结果并提示剩余文件写入成功 |
| 返回资产 | 回到资产页，不撤销已写入结果 |

#### 状态与恢复

| 状态 | 页面表现与可恢复操作 |
|---|---|
| 全部成功 | 显示来源 commit、目标和逐文件结果；不变项仍标识为不变 |
| 部分失败 | 明确区分已写入与未处理项，显示失败原因和重试入口，不显示整体成功 |
| 全部失败 | 保留计划摘要、目标路径和修复建议，允许修复后重新检查 |
| 重试时计划变化 | 不沿用旧确认，返回重新 dry-run 与确认 |
| 重试成功 | 仅将实际处理成功的项目更新为成功结果 |

#### 权限与写入边界

　　结果页本身只读；只有用户点击重试后才继续目标写入。已写入项不会因离开页面被自动撤销，失败项不得记为成功。

### 4.12 高级自定义目录弹窗

#### 页面目的

　　为便携版、非标准安装目录或有特殊目录约束的企业环境提供显式高级入口。标准分发已经完成自动目录解析，普通用户无需进入本弹窗或手动编辑配置文件。

#### 入口

　　在分发配置页点击一次“高级自定义”，系统读取本机配置成功后直接打开弹窗；也可在高级模式中点击“管理自定义”或添加入口。当前资产必须可读取，且存在支持该资产类型的目标工具。

#### 区域与字段

| 区域/字段 | 展示与填写要求 |
|---|---|
| 当前资产上下文 | 说明正在为哪个 `AssetRef` 配置特殊目录，并提示标准分发无需此配置 |
| 目标工具 | 必填下拉框，仅列出支持当前资产类型的目标 |
| 自定义基准目录 | 必填；保留手动输入，并提供“选择目录”按钮调用系统目录选择器；支持相对路径、绝对路径和 `~` 用户目录，示例为 `D:\AI\project` 或已包含官方目录的 `D:\AI\project\.trae` |
| 已有配置回填 | 高级模式管理当前已配置目标时，输入框预填该目标解析后的现有根目录；若已是官方工具目录，保存时不重复追加；展示路径清理 Windows 扩展前缀，不改变保存语义 |
| 路径说明 | 输入工具官方目录的上一级基准目录，系统按目标自动追加官方目录；相对路径以当前工作区为基准，最终逐文件位置以 dry-run 为准 |
| 保存影响 | 明示写入 `adock.local.yaml` 并进入高级自定义模式；保留已有本机目标与发布通道，不修改共享 `adock.yaml` |
| 操作按钮 | 提供取消与“保存并使用”；保存中显示处理中状态 |
| 错误区域 | 在弹窗内显示校验或保存失败原因 |

#### 操作与反馈

| 操作 | 反馈与结果 |
|---|---|
| 选择目录并确认 | 将系统返回的目录回填到自定义基准目录输入框，不立即保存；用户仍可修改 |
| 取消目录选择 | 关闭系统选择器，保留原输入和当前弹窗，不修改配置 |
| 保存有效配置 | 关闭弹窗，使旧分发计划失效，进入高级自定义模式并重新读取当前资产目标选项，保留刚保存的目标为选中项 |
| 取消或关闭 | 不修改本机目标配置，不改变当前工作区或分发模式 |
| 保存后继续分发 | 在高级模式选择目标并重新生成 dry-run，以逐文件计划确认最终位置 |
| 返回标准分发 | 点击项目级或用户级恢复自动目录解析；已保存配置继续保留，但不参与标准模式 |

#### 状态与恢复

| 状态 | 页面表现与可恢复操作 |
|---|---|
| 自定义基准目录为空 | 提示输入自定义基准目录，不提交保存 |
| 目录选择器打开失败 | 保留当前输入并提示原因，仍可手动输入后保存 |
| 无受支持目标 | 不提供无效保存入口，返回分发页查看支持范围 |
| 正在保存 | 显示“正在保存”状态，避免重复提交 |
| 保存失败 | 弹窗保持打开，显示目标与失败原因，保留输入供修正 |
| 保存后无可用计划 | 返回分发配置检查资产类型、目标和 revision，不伪造成功计划 |

#### 权限与写入边界

　　仅写当前工作区的本机覆盖配置，保留其他本机目标与发布通道，不修改共享配置、资产正文或目标文件。最终资产文件位置仍由目标工具适配规则决定，并以新的 dry-run 为准。

### 4.13 协作说明页

#### 页面目的

　　让新成员和资产负责人从统一入口找到资产规范、维护责任和评审路径，同时明确桌面端与 Git 平台的职责边界。

#### 入口

　　点击一级导航“协作说明”；资产错误和空工作区中的规范入口也可引导用户查看相关说明。配置错误或非 Git 状态下仍可访问本页。

#### 区域与字段

| 区域/字段 | 展示与填写要求 |
|---|---|
| 团队仓库入口 | 提供“打开团队仓库”操作 |
| 新成员入口 | 提供 README、Prompt 目录与模板规范、Skill 目录与资源规范、Schema 与工作区校验入口 |
| 当前边界 | 明示 MCP 注册与 Eval 不在 MVP 范围，不提供不可用操作按钮 |
| 资产负责人 | 按资产领域或 `AssetRef` 展示 owners；说明 CODEOWNERS 与合并权限由 Git 平台执行 |
| 评审边界 | 说明 AgentDock 提供校验和 diff，不复制 MR/PR 评审状态 |
| 标准变更流程 | 修改资产 → 本地校验 / diff → 提交 MR / PR → 负责人评审合并 → 创建不可变 `v*` 标签 → 显式移动 `prod` |
| 回滚协作说明 | 说明回滚也只生成工作区恢复变更，仍需经过同样的提交与评审路径 |

#### 操作与反馈

| 操作 | 反馈与结果 |
|---|---|
| 打开团队仓库或文档 | 打开对应外部入口，并给出明确反馈 |
| 查看负责人 | 定位资产维护责任，不将其解释为桌面端授权 |
| 查看标准流程 | 理解普通修改和回滚都需经过 Git 评审 |

#### 状态与恢复

| 状态 | 页面表现与可恢复操作 |
|---|---|
| 工作区无资产 | 保留规范入口和流程说明，不伪造负责人 |
| 配置错误或非 Git | 仍可查看协作边界与流程，但不据此开放版本或分发操作 |
| 外部入口打开失败 | 保留文档名称与链接目标，提供重试或复制入口，不显示已打开成功 |

#### 权限与写入边界

　　本页只读，不修改资产、owners、CODEOWNERS 或评审状态。外部仓库和文档的访问权限仍由原平台控制。

## 5. 全局反馈与异常表达

### 5.1 反馈层级

| 反馈类型 | 页面要求 |
|---|---|
| 成功反馈 | 打开工作区、初始化、刷新、创建标签、移动 `prod`、生成恢复变更和保存高级自定义目录后，使用短时提示并同步更新相关页面事实 |
| 校验结果 | 反馈通过与错误数量；存在单资产错误时，详情必须能定位文件和原因 |
| 阻塞错误 | 在对应页面或弹窗内显示，不仅依赖短时提示；至少包含操作对象、失败原因和下一步建议 |
| 冲突提示 | 与计划项或恢复路径相邻展示，明确是否允许继续以及可采取的恢复动作 |
| 加载状态 | 打开工作区、读取详情、读取差异、生成计划和保存配置时显示处理中状态，避免重复操作 |
| 部分失败 | 保留逐项结果，不以整体成功提示覆盖失败事实 |

### 5.2 取消、刷新与计划失效

- 取消弹窗不向用户显示操作成功；对应标签、资产、配置或目标文件保持不变。
- 刷新只更新事实源，不自动重试标签、回滚或分发写操作。
- 外部 Git 或文件变化导致当前预览失效时，要求重新读取或预览，不继续沿用旧确认。
- 本地列表、历史、标签、回滚和分发不以 Git 推送或 MR/PR 为前置条件；网络状态不改变上述本地操作的权限边界。
